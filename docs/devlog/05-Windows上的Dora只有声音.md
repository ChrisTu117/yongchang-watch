# 开发者日志 05：Windows 上的 Dora 只有声音，没有画面

2026-11-27

日志 04 结尾说，Windows 上的 Dora 还没在真机上看过。这一篇记的就是真机上遇到的两个问题，以及原因是怎么找到的。

## 现象：有音乐，没有画面

11 月 21 日，在一台 Windows 电脑上装好 Dora SSR 1.10.2，用命令行 `Dora cli run` 运行本项目。标题音乐响了，窗口里却看不到游戏。Dora 的日志里，游戏打出了 `scene: title`，说明 Lua 代码在跑；可是 Linux 上紧跟着出现的 `first render submitted` 这一行，Windows 上没有。

先排除了两种猜测：在 Linux 上打开虚拟声卡再跑一遍，画面照常，说明不是声音模块拖住了渲染；LoveNode 的画布尺寸和 DPI 两边一样，也不是缩放问题。

## 原因：IDE 盖着时，引擎不画

Windows 和 macOS 版的 Dora 启动后会显示内置的 Web IDE。我们去读了 Dora 1.10.2 的源码：`Director::doRender` 一开头就判断 IDE 是否可见，可见就直接返回，这一帧不画场景，游戏逻辑和声音不受影响。从 IDE 里点“运行”时，IDE 会先把自己收起来；用命令行 `cli run` 启动则不会。有声音、没画面、日志里缺 first render，三个现象都对上了。

修法只有几行：`init.lua` 启动时，如果是 Windows 或 macOS 且开着 Web IDE，就发一个 `AppWebView` 事件把 IDE 收起，写法照着 Dora 自带脚本启动导入工具时的做法。想回到 IDE，按 Ctrl+Shift+H。Dora 兼容静态检查也加了一条，确认 `init.lua` 里有这段代码〔C6〕。

## 第二个坑：工作目录

11 月 27 日复测时，Dora 窗口一片黑，命令行报 `connection closed`。这次不是游戏的问题：Dora 的日志写着找不到 `Script.Dev.Bootstrap`。源码里，Windows 版 Dora 把“当前工作目录”当作自带脚本的位置，而 PowerShell 的 `Start-Process` 默认沿用当时所在的文件夹。启动时加上 `-WorkingDirectory`，指向 Dora 所在的文件夹，就正常了。这一条也写进了发行版的运行说明。

两处都改好以后，在 Windows 真机上：IDE 自动收起，标题画面正常，点进第一夜走完教学，有声音，按 Esc 用菜单退出〔M2〕。

## 演示视频也是脚本“玩”出来的

演示视频没有用录屏软件。`tools/record_demo.sh` 在虚拟显示器里以 1920×1080 启动游戏，按固定的 1/30 秒一步推进，每一帧截图直接交给 ffmpeg 编码。鼠标的移动、点击和按键由脚本发出，走的是和端到端测试相同的输入入口，所以视频里的每个操作都是游戏真实处理过的。声音按游戏记录的事件，用 `assets/sfx/` 里的原创音效和音乐重新混成音轨，音量和同时发声的上限照搬游戏里的音频模块。这样画面不掉帧，声音里也不会混进别的东西。成片 3 分钟出头，已发到 B 站〔M3〕。

教训：静态检查和 Linux 上的实测都通过，并不能代替在目标平台上看一眼。这次两个问题都出在“怎么启动”，而不是游戏本身。
