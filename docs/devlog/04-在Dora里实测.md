# 开发者日志 04：在 Dora 里真跑一遍，踩到的两个坑

2026-11-21

此前的 Dora 兼容工作都停在“静态”层面：按 Dora 官方指南写入口、扫描代码里有没有 LuaJIT 专有写法、用 Lua 5.5 把规则测试跑一遍。这些都通过了，但我们一直记着 Dora 作者在博客里的提醒：Running: yes 不等于游戏真的做好了。所以这一次直接在 Dora SSR 1.10.2 的 Linux 版里运行 `init.lua`，用真实的鼠标键盘事件去点〔C18〕。

## 坑一：点不动

标题画面完全正常，中文字体、按钮、飘着的孔明灯都在；把鼠标移到按钮上，按钮也会变亮。可是一点击，什么都没发生。

我们在游戏的输入回调里临时加了日志，再点一次，Dora 的日志里出现的是 `touchpressed`，而不是 `mousepressed`。原来 Dora 的 LoveNode 把鼠标点击当作触摸送给游戏，鼠标移动则照常走 `mousemoved`。桌面上的 LÖVE 正好相反。

解决办法是加一个很小的输入转接模块 `src/input.lua`：鼠标回调和触摸回调都接，统一交给游戏；如果同一次点击从两条路各来一次（触摸屏上的 LÖVE 就会这样），同一位置 50 毫秒内的第二次按下只算一次。端到端测试里加了对应的检查：模拟 Dora 式的触摸点击进出“操作说明”，以及同一次点击从两条路送来时只处理一次〔C5〕。

## 坑二：底栏被盖住

能点以后，进到守夜画面，发现底部选择弓手、鸟铳、烽火的卡片被一条灰色工具栏盖住了，舞龙显字里的“继续”按钮也只露出一半。

这条工具栏是 Dora 运行项目时自带的开发工具栏（Quit、Reload 等）。我们读了 Dora 安装包里自带的脚本，确认它高 50、默认显示。于是在 `init.lua` 里算缩放时预留出这 50 的高度，把整个游戏放在工具栏上方，两侧留黑边。游戏代码本身不用改，桌面 LÖVE 版也不受影响。

## 现在的检查

`tools/check_dora_runtime.sh` 会启动 Dora，运行本项目，然后依次：点“从第一夜开始”、按空格翻完剧情、把鼠标移向海面、点敌台安排弓手、点西门迎百姓、按 Esc 用菜单返回标题、再点“退出游戏”。每一步都从 Dora 日志里核对游戏打出的进度行，最后确认日志里没有报错〔C18〕。

还没测的是 Windows 上的 Dora：声音（这台测试机没有声卡）和真显卡下的画面，要在真机上看一眼〔M2〕。
