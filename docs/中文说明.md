# 中文说明：代码怎么组织、关键地方怎么实现

给参赛者本人看，也给想读代码的评委看。读完能回答“这段代码做什么、为什么这样写、AI 做了哪些事”。

## 一、整体结构

```
main.lua / conf.lua     LÖVE 11.5 入口和窗口设置（1280×720，可缩放）
init.lua                Dora SSR 1.10 入口：LoveNode("main.lua") + 摄像机适配 + 收起 Windows/macOS 版 Dora 的内置 IDE
src/app.lua             场景切换、存档、把鼠标坐标换算成逻辑坐标
src/gfx.lua             画面工具：960×540 逻辑画面等比缩放；文字按实际像素生成字体
src/audio.lua           音效和音乐；没有声卡时自动静默
src/sim/world.lua       一夜的全部规则（不调用 love.*，可单独测试）
src/sim/stroke.lua      描笔画的评判
src/sim/bot.lua         自动测试用的“机器人玩家”
src/data/               地图、数值、关卡、剧情文字、笔画模板
src/scenes/             标题、剧情、守夜、舞龙显字、终章、操作说明
src/autotest.lua        端到端自动测试脚本（只有加 --autotest 参数才加载）
tests/                  纯 Lua 单元测试
tools/                  打包、生成音频和字体、各项检查
```

最重要的设计：**规则和画面分开**。`src/sim/` 里只有纯 Lua 计算，不碰画面和声音，所以能在普通 Lua 解释器里跑上千条测试，也能在 LuaJIT（LÖVE 用的）和 Lua 5.5（Dora 用的）里各跑一遍，结果完全一样。

## 二、“望”是怎么实现的

1. 每个敌人每一帧算一次“是否被照亮”（`World:isLit`）：在堡内、在光束扇形里、在某个守城单位的灯笼半径内、在城门火把旁、在孔明灯范围内，满足任一条就是亮的。
2. 光束是一个扇形：以望楼为圆心，半径 430，半角 16°〔C17〕。判断点是否在扇形内，就是比距离和角度差（`U.angdiff`）。
3. 守城单位找目标时只看“被照亮且在射程内”的敌人，挑离城门最近的那个打（`World:updateTowers`）。
4. 画面上的黑暗是一张画布：先铺夜色，再用“相加”模式画上各处光斑和光束，最后用“相乘”模式盖在地图上。规则里的“照亮”和画面上的亮处用的是同一组半径。

## 三、“守”和“守望相助”

- 城门有耐久。关着的门被敌人砸，耐久归零就被攻破，之后敌人可以直接进堡，扣“堡安”；点被攻破的门可以花 4 点民力修好（恢复一半耐久）。东门有瓮城，耐久是别的门的 1.6 倍〔C17〕。
- 百姓沿路走到门前等。门开着就进堡，民力 +2；等 14 秒没人开门就离开；被敌人碰到会被冲散〔C17〕。
- 屯田：每 12 秒民力 +1〔C17〕，对应资料里“堡内百余亩农田，战时可供自给”。
- 第一夜有四步教学，每一步完成前夜晚时钟不走，敌人也不来，玩家不会在学操作时被打。

## 四、数值是怎么定的

`tests/test_balance.lua` 让机器人玩家各打一遍三夜，要求：
- 按正常策略（照着敌人、按计划建塔、有百姓就开门、敌人近了就关门）三夜都能守住，且“堡安”至少剩 40〔C10〕；
- 什么都不做，三夜都会失守；
- 光束永远朝西、不放孔明灯（不“望”），第二、三夜明显守得更差；
- 从不开门（不迎百姓），救不到人，能建的守城单位更少。

开发时这组测试真的抓到过一个问题：最初烽火照得太亮，不用光束也能守住第二夜，“望”就失去意义。后来把烽火、灯笼和城门火把的照明半径调小，测试才通过。

## 五、舞龙显字

- 每个字的笔画是田字格里的几个坐标点（`src/data/strokes.lua`），笔顺和汉典的笔顺编号一致（天 1134、下 124、太 1344、平 14312），测试会核对〔C12〕。
- 玩家按住鼠标拖出一条线。评判（`Stroke.evaluate`）看四件事：起笔点、收笔点、方向是否写反、整条线和模板的平均偏差。两条线都按长度均匀取 16 个点再比〔C17〕，所以写快写慢不影响。
- 连错三次，可以“请师傅带一笔”，不会卡关。
- 龙有九节（龙头、七节龙身、龙尾）〔C17〕，对应资料里拼字龙灯“龙头、龙尾与七节龙身各自独立”。每节跟着前一节走，保持固定间距。

## 六、Dora 兼容

- Dora 1.10 的 `LoveNode` 能运行 LÖVE 11.5 项目，但用的是 Lua 5.5，不是 LuaJIT。所以代码里不用 LuaJIT 专有的东西（ffi、jit、bit、setfenv、整除符号 `//` 等），数字显示统一用 `U.int`（Lua 5.5 会把 3.0 显示成“3.0”）。`tools/check_dora_compat.py` 会扫描代码并用 Lua 5.5 编译所有文件。
- 按 Dora 官方指南：游戏代码不碰 Dora 接口，`init.lua` 不碰 `love.*`；屏幕适配在 Dora 这边用摄像机缩放一次。
- 字体：Dora 用 stb_truetype 读字体，所以把 Noto 字体的 CFF 轮廓转成了 TrueType 轮廓。
- 在 Dora 1.10.2 Linux 版实测发现两件事：一是 LoveNode 把鼠标点击作为 `love.touchpressed` 送来，而桌面 LÖVE 走 `love.mousepressed`，所以 `src/input.lua` 两种都接，同一位置 50 毫秒内的第二次按下视为同一次；二是在 Dora 里运行时底部有一条 50 高的开发工具栏，`init.lua` 计算缩放时预留这块高度，把游戏放在上方。`tools/check_dora_runtime.sh` 会在 Dora 里用真实鼠标键盘事件把这些走一遍〔C18〕。
- Windows 上的 Dora 用命令行运行时只有声音没有画面。读 Dora 1.10.2 源码查到原因：Windows 和 macOS 版启动后显示内置 Web IDE，`Director::doRender` 在 IDE 盖住窗口时直接返回，不绘制场景，但逻辑和声音照常运行；IDE 的运行按钮会先收起 IDE，命令行 `cli run` 不会。`init.lua` 末尾在这两个平台上发出 `emit("AppWebView", "/ide/hide", false)`，和 Dora 自带的 `Script/Dev/Entry.yue` 启动导入工具时的写法一样。Linux 版没有内置 IDE 窗口，这段不执行。

## 七、AI 做了什么、人做了什么

- AI（Claude Code）：读规则和资料、设计玩法、写全部代码和测试、合成音频、生成字体子集、写文档初稿。
- 参赛者：决定参赛、报名、在 Windows 上试玩、录视频、在社区发布和互评、提交作品。
- 详见 `docs/AI使用与素材声明.md`。

## 八、常见问题

**问：为什么不用图片素材？**
答：画面全用代码画（几何图形），没有授权风险，体积小，Dora 和 LÖVE 渲染结果一致。

**问：音乐是 AI 生成的吗？**
答：不是 AI 音频模型生成的。`tools/gen_audio.py` 用数学公式合成：拨弦音色用 Karplus-Strong 算法，锣是几个不成倍数的正弦波叠加后衰减，旋律只用五声音阶（宫商角徵羽）。同一脚本重新运行，得到的文件逐字节相同。

**问：怎么证明游戏能玩通？**
答：`bash tools/check_all.sh` 会在虚拟显示器里启动真正的 LÖVE，用模拟的鼠标键盘从标题玩到终章，再从菜单退出，全程截图。

**问：史实准确吗？**
答：只用赛事提供资料里的说法，每条都标了出处（`docs/文化资料与出处.md`）。地图是示意，不按比例。

**问：16 天内完成的证据？**
答：仓库在主题公布后新建，git 提交历史从 2026-11-21 开始。
